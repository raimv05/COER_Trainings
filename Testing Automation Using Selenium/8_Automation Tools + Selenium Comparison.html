Automation Tools + Selenium Comparison

Selenium is not the only automation solution — and by this point students know it well enough to see where it fits next to Playwright and Cypress, rather than in isolation.

8.1

Selenium

Selenium

Selenium officially supports browser automation through WebDriver, and its ecosystem includes components such as Selenium Grid for distributed execution across machines and browsers.

Best known for Browser automation Cross-browser testing Large ecosystem Multiple programming languages Enterprise legacy suites
8.2

Playwright

Playwright

Built by Microsoft, with official support across JavaScript/TypeScript, Python, Java, and .NET.

Languages JavaScript/TypeScript Python Java .NET
Strong areas Modern web applications Auto-waiting Browser contexts Parallel execution
Browser engines Chromium Firefox WebKit

import { test, expect } from '@playwright/test';

test('homepage test', async ({ page }) => {

    await page.goto('https://example.com');

    await expect(
        page.locator('h1')
    ).toBeVisible();

});
8.3

Cypress

Cypress

Cypress is heavily focused on modern web application testing and supports both end-to-end and component testing. Its current documentation also covers accessibility testing and CI-oriented workflows.

login.cy.js 
describe('Login Test', () => {

    it('should login successfully', () => {

        cy.visit('https://example.com');

        cy.get('#username')
          .type('student');

        cy.get('#password')
          .type('Password123');

        cy.get('#login')
          .click();

    });

});

The shape of a Cypress test

Cypress tests commonly follow the same pattern: visit a page, query elements, interact with them, then assert the resulting state — the same Arrange–Act–Assert idea from Hour 2, expressed in Cypress's own vocabulary.

Architecture is the real dividing line

Cypress itself explicitly contrasts its architecture with Selenium's: Cypress executes inside the application's own browser run loop, rather than driving the browser externally the way Selenium's WebDriver-style model does. That single difference explains most of the auto-waiting and speed behavior students will notice when they try both.

Important Teaching Point
