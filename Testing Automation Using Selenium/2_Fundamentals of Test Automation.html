Fundamentals of Test Automation

Automation isn't just "writing scripts." It's a disciplined lifecycle, a filter for deciding what deserves to be automated, and a structure — Arrange, Act, Assert — that holds regardless of tool or language.

2.1

Automation Testing Lifecycle

Automation isn't just "open a tool and start scripting." It follows a repeatable lifecycle — skip a stage and the suite you build tends to become fragile or unmaintainable within a few releases.

01 Requirement Analysis
02 Test Case Identification
03 Automation Feasibility

05 Framework Design
06 Script Development
07 Execution
08 Reporting
09 Maintenance

Why "Maintenance" is stage nine, not an afterthought

Applications change. Locators break, flows shift, new fields appear. A lifecycle that ends at "Execution" produces a suite that quietly rots — treating maintenance as a defined stage is what keeps a regression suite trustworthy release after release.

Automation Test Case Example

Before any script is written, a manual test case is documented in plain, structured language. Automation then converts each of these actions into code — nothing more, nothing less.

TC_LOGIN_001 Verify valid user login
PreconditionUser account exists.
Steps
  • 1 Open application
  • 2 Enter username
  • 3 Enter password
  • 4 Click Login
Expected: Dashboard should appear.
↳ In section 2.4, these four steps become three lines of Arrange–Act–Assert code.
2.4

Basic Automation Structure

Almost every automated test — regardless of language or tool — follows the same three-part shape: set the stage, perform the action, check the outcome.

Arrange Set up
Act Perform
Assert Verify
LoginTest.java 
// Arrange
driver.get("https://example.com");

// Act
driver.findElement(By.id("username")).sendKeys("student");

// Assert
Assert.assertTrue(driver.getTitle().contains("Example"));

Not a Selenium-only idea

This Arrange–Act–Assert shape shows up well beyond Selenium. Modern frameworks like Cypress structure their own examples the same way — a setup step, an action, then an assertion — because the pattern reflects how verification logically has to work, not a quirk of one tool.

2.5

First Automation Logic Without Selenium

Before introducing Selenium, it helps to strip automation down to its bare logic — no browser, no driver, just plain Java deciding pass or fail.

LoginTest.java 
public class LoginTest {

    public static void main(String[] args) {

        String username = "student";
        String password = "Password123";

        if (username.equals("student")
                && password.equals("Password123")) {

            System.out.println("Login Successful");

        } else {

            System.out.println("Login Failed");
        }
    }
}

What this demonstrates

Input
Action
Validation
Result

The idea scales up unchanged

Automation testing follows this exact same idea — input, action, validation, result — except the "action" happens against a real, running application through a browser or API instead of two hard-coded strings.
