6.1

Locators

A locator is how WebDriver finds an element on the page. Selenium supports eight strategies:

id
name
className
tagName
linkText
partialLinkText
cssSelector
xpath
Locator.java 
driver.findElement(By.id("username"));
6.2

Basic Form Automation

The same locate → interact pattern repeats for every field on a form.

FormAutomation.java 
driver.findElement(By.id("username"))
      .sendKeys("student");

driver.findElement(By.id("password"))
      .sendKeys("Password123");

driver.findElement(By.id("login"))
      .click();
6.3

Assertions

An action without an assertion isn't a test — it's just automation of clicks. Assertions are what turn a script into a verifiable check.

Title assertion
TitleAssert.java 
String title = driver.getTitle();

Assert.assertTrue(
    title.contains("Dashboard"),
    "Dashboard was not displayed"
);
Text assertion
TextAssert.java 
String actualMessage =
        driver.findElement(By.id("message"))
              .getText();

Assert.assertEquals(
        actualMessage,
        "Login successful"
);
6.4

Explicit Waits

This is an important professional concept — the line between a script that merely "works on my machine" and one that survives real-world timing variance.

✕ Avoid
Avoid.java 
Thread.sleep(5000);
  • Wastes time — waits the full duration even if the page was ready instantly
  • Creates flaky tests — too short on a slow day, too long on a fast one
  • Doesn't adapt to application state — it's a guess, not a check
✓ Prefer
Prefer.java 
WebDriverWait wait =
        new WebDriverWait(driver, Duration.ofSeconds(10));

WebElement loginButton =
        wait.until(
            ExpectedConditions.elementToBeClickable(
                By.id("login")
            )
        );

loginButton.click();
6.5

Complete Selenium Test

Everything from this hour, combined into one runnable test: a maximized browser, an explicit wait, a real assertion, and a guaranteed quit() — even if the assertion fails.

LoginAutomationTest.java 
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.openqa.selenium.support.ui.WebDriverWait;
import org.testng.Assert;
import org.testng.annotations.Test;

import java.time.Duration;

public class LoginAutomationTest {

    @Test
    public void loginTest() {

        WebDriver driver = new ChromeDriver();

        try {

            driver.manage().window().maximize();

            driver.get("https://example.com");

            WebDriverWait wait =
                    new WebDriverWait(
                            driver,
                            Duration.ofSeconds(10)
                    );

            WebElement element =
                    wait.until(
                            ExpectedConditions.visibilityOfElementLocated(
                                    By.tagName("h1")
                            )
                    );

            String heading = element.getText();

            Assert.assertFalse(
                    heading.isEmpty(),
                    "Heading was not displayed"
            );

        } finally {

            driver.quit();
        }
    }
}

Trainer note

example.com is used here only to demonstrate the mechanics — the wait, the assertion, the guaranteed cleanup. For actual login automation, substitute a dedicated QA/demo application with known, stable selectors and credentials.
