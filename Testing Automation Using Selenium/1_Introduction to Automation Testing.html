Introduction to Automation Testing

Before writing a single line of test automation, every SDET needs a clear mental model of what testing actually is, where manual effort breaks down at scale, and what automation genuinely solves — and doesn't.

What is Software Testing?

Software testing is the process of evaluating software to determine whether it behaves according to expected requirements. Every test starts from the same question: given a specific input, does the application produce the expected outcome?

What is Manual Testing?

In manual testing, a human tester performs every action by hand — clicking, typing, and visually verifying the result. Here's the Amazon login example carried out manually:

01 Open browser
02 Open application
03 Enter username
04 Enter password
05 Click Login
06 Verify dashboard
07 Logout

The scaling problem

If this test needs to be executed 100 times — across builds, browsers, or environments — the tester repeats all seven steps by hand, every single time. Nothing here changes; only the effort multiplies.

What is Automation Testing?

Automation testing replaces repeated human action with software that executes predefined test cases on its own. The manual chain of "Human → Browser → Click → Verify" becomes a scripted pipeline:

Real-life example — a banking application

Every time developers release a new version, QA must re-verify login, logout, balance, fund transfer, account statement, and password reset — across roughly 500 regression test cases. Done manually, that verification can take several days. Automation can execute the same suite repeatedly with minimal human intervention.

Implementing it: automating the login test

Here's how the same seven-step manual login test from 1.2 gets expressed as an automation script. Each line maps directly to one manual step — this is the core idea students should hold onto: automation doesn't invent new steps, it scripts the ones a human already performs.

login.test.js 
const { Builder, By, until } = require('selenium-webdriver');

// Step 1–2: open browser, open application
const driver = await new Builder().forBrowser('chrome').build();
await driver.get('https://amazon.com/login');

// Step 3–4: enter username and password
await driver.findElement(By.id('username')).sendKeys('student@gmail.com');
await driver.findElement(By.id('password')).sendKeys('Password123');

// Step 5: click Login
await driver.findElement(By.id('loginBtn')).click();

// Step 6: verify dashboard — this replaces the human eye
await driver.wait(until.urlContains('dashboard'), 5000);
console.log('PASS: dashboard reached');

// Step 7: logout, close browser
await driver.findElement(By.id('logout')).click();
await driver.quit();
01–02 Builder + get() 03–04 sendKeys() 05 click() 06 wait + urlContains() 07 click(logout) + quit()

Advantages of Automation Testing

None of these benefits come from automation being "smarter" than a human tester — they come from removing repetition from the equation.

Faster execution

100 tests can potentially execute much faster than the same tests run manually.

Repeatability

The exact same test can be executed again and again without drift in how it's performed.

Accuracy

Reduces human errors such as a wrong username, a missed click, or a skipped validation.

Regression testing

Automation is especially valuable for regression suites that must be re-run every release.

Parallel execution

Tests can run across multiple browsers or machines at the same time.

CI/CD integration

Automated tests can run automatically the moment developers commit new code.

1.5

Limitations of Automation Testing

Automation does not replace manual testing. It's a tool for repeatable, well-defined checks — not for judgment calls.

Automation is not ideal for:

Exploratory testing Usability testing Visual judgement Ad-hoc testing Tests that change constantly One-time tests
