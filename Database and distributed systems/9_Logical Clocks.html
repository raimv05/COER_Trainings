9.1 DEFINITION

What is a logical clock?

A logical clock assigns a number to an event to help determine event ordering.

It does not attempt to represent real-world time. There's no seconds, no milliseconds, no wall-clock date — just a counter that goes up in a way that respects the order events actually happened in.

This is the direct answer to Hour 7's problem: if physical clocks can't be trusted, build a clock that doesn't need to match real time at all — it only needs to get the order right.

9.2 HAPPENED-BEFORE RELATION

Lamport's notation

A → B

meaning: Event A happened before event B.

This simple arrow is the entire foundation of ordering in distributed systems. Everything else this hour is just precise rules for when you're allowed to write it.

9.2 HAPPENED-BEFORE RELATION

The three rules

1

Same process

If A happens before B in the same process (in program order)...

A → B
2

Message

If A sends a message and B is the event of receiving it...

A → B
3

Transitivity

If A → B and B → C, then it follows that...

A → C

These three rules are all Lamport needs — sequencing within a process, causality across a message, and chaining those relationships together.

9.4 LOGICAL CLOCK RULES

The core Lamport-clock algorithm

Before an event

clock = clock + 1

Sending a message

clock = clock + 1
send(timestamp)

Receiving a message (T)

clock = max(localClock, T) + 1

The receive rule is the clever part: taking the max of your own clock and the sender's timestamp guarantees your clock jumps forward far enough to stay consistent with what you just learned about — while the +1 guarantees the receive event is still ordered strictly after the send.

Hour 9 — Key takeaways

🔢 Order, not time

A logical clock assigns numbers to order events — it never tries to represent real-world time.

➡️ Happened-before is built from 3 rules

Same-process order, message send/receive, and transitivity chain together to define A → B.

🧮 The algorithm is simple

+1 before any event, +1 and send on message send, max(local, received) + 1 on receive.

🧪 It's mechanical, not magical

Running the simulator shows the same three rules apply every single time, regardless of how many events pile up.
