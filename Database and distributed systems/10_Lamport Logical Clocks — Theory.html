10.2 WHY LAMPORT CLOCKS?

Ordering without a perfect global clock

Because distributed systems cannot depend on a perfect global clock (Hour 7), Lamport clocks let us create an ordering that respects causality instead.

If A → B, then L(A) < L(B)

Whenever one event truly happened before another, the logical clock guarantees the numbers reflect that — a property physical timestamps alone couldn't promise.

10.2 WHY LAMPORT CLOCKS? — THE CATCH

An important limitation

LIMITATION

L(A) < L(B) does not necessarily mean A caused B.

The implication only runs one direction. Lamport clocks guarantee that causality implies ordering — but two completely unrelated events on different processes can still end up with L(A) < L(B) purely by coincidence, with no causal link between them at all.

This is exactly where vector clocks become useful — they can tell the difference between "happened before" and "just numbered lower."

10.3 SIMPLE LAMPORT CLOCK CLASS

Putting the algorithm into code

LamportClock.java 
class LamportClock {

    private int clock = 0;

    public int tick() {
        return ++clock;
    }

    public int receive(int receivedClock) {

        clock = Math.max(clock, receivedClock);

        return ++clock;
    }

    public int getClock() {
        return clock;
    }
}
10.3 SIMPLE LAMPORT CLOCK CLASS

Reading the class against the rules

clock = 0Every process starts its own independent Lamport clock at zero.
tick()Implements the "before an event" and "sending" rules in one line: increment, then return the new value — used for local events and as the timestamp attached to an outgoing message.
receive(receivedClock)Implements the receive rule exactly: clock = max(clock, receivedClock), then the pre-increment ++clock applies the final +1.
getClock()A read-only peek at the current value — useful for logging or debugging without advancing the clock.

Three tiny methods, and this single class is enough to reproduce every clock value from the A(1)→B(2)→C(3)→D(4) example we just walked through.

RECAP

Hour 10 — Key takeaways

🔢 The numbers follow the rules

Local events increment by 1; receiving a message jumps the clock to max(local, received) + 1.

🧭 Causality implies order

If A → B, Lamport clocks guarantee L(A) < L(B) — a promise physical timestamps can't make.

⚠️ Order doesn't imply causality

L(A) < L(B) doesn't mean A caused B — the reverse implication doesn't hold, which motivates vector clocks.

☕ It's a tiny class

tick(), receive(), and getClock() are all that's needed to implement the full algorithm.
