12.1 WHY DO WE NEED VECTOR CLOCKS?

What Lamport clocks can't tell us

LAMPORT CLOCKS CAN TELL US
A < B
BUT CANNOT ALWAYS TELL US

Whether A caused B, or whether the events were completely independent.

Vector clocks solve this by maintaining a full vector — one counter per process — instead of a single number. For three processes, every clock starts identical:

P1 = [0,0,0]
P2 = [0,0,0]
P3 = [0,0,0]
12.2 VECTOR CLOCK RULES

Walking through the rules

Internal event at P1:
0,0,0
→
1,0,0
Another event at P1:
2,0,0
P1 sends to P2:
P1 = [3,0,0]
P2 currently holds:
P2 = [0,0,0]
Component-wise max:
max([0,0,0], [3,0,0])
Then increment P2's own slot:
[3,1,0]
12.3 JAVA IMPLEMENTATION

The VectorClock class

VectorClock.java 
import java.util.Arrays;

class VectorClock {

    private int[] clock;

    public VectorClock(int numberOfProcesses) {
        clock = new int[numberOfProcesses];
    }

    public void tick(int processId) {
        clock[processId]++;
    }

    public void receive(
            int[] receivedClock,
            int processId) {

        for (int i = 0; i < clock.length; i++) {
            clock[i] = Math.max(clock[i], receivedClock[i]);
        }

        clock[processId]++;
    }

    public int[] getClock() {
        return clock.clone();
    }

    @Override
    public String toString() {
        return Arrays.toString(clock);
    }
}
12.3 JAVA IMPLEMENTATION

Reading the class

int[] clockOne slot per process — this is the whole difference from a Lamport clock's single integer.
tick(processId)Increments only this process's own slot — never anyone else's.
receive(...)Takes the component-wise max across the entire vector, then increments its own slot — exactly the rule from 12.2.
clock.clone()Returns a copy so the caller can't accidentally mutate this process's internal state.
12.4 COMPLETE VECTOR CLOCK DEMO

Three processes, one scenario

VectorClockDemo.java 
public class VectorClockDemo {

    public static void main(String[] args) {

        VectorClock p1 = new VectorClock(3);
        VectorClock p2 = new VectorClock(3);
        VectorClock p3 = new VectorClock(3);

        // P1 performs an event
        p1.tick(0);
        System.out.println("P1: " + p1);

        // P1 performs another event
        p1.tick(0);
        System.out.println("P1: " + p1);

        // P1 sends its clock to P2
        int[] message = p1.getClock();
        p2.receive(message, 1);
        System.out.println("P2 after receiving: " + p2);

        // P3 performs an independent event
        p3.tick(2);
        System.out.println("P3: " + p3);
    }
}
12.4 COMPLETE VECTOR CLOCK DEMO

Expected conceptual output

console output
P1: [1, 0, 0]
P1: [2, 0, 0]
P2 after receiving: [2, 1, 0]
P3: [0, 0, 1]

Notice P3's vector only has its own slot touched — it had no contact with P1 or P2, so it stays fully independent of them.

12.5 COMPARING VECTOR CLOCKS

When one vector dominates another

A = [2,1,0]
B = [2,3,0]

Because every component of A is ≤ the matching component of B, and at least one is strictly smaller (1 < 3)...

A → B

A vector dominates another exactly when it's less-than-or-equal in every slot, with at least one strictly less. This is the vector-clock generalization of the happened-before relation.

12.5 COMPARING VECTOR CLOCKS

When neither vector dominates

A = [2,1,0]
B = [1,0,3]

A is bigger in slot 0 and 1, but B is bigger in slot 2 — neither vector dominates the other.

A || B

A and B are concurrent events — genuinely independent, with no causal relationship either way. This is one of the most important differences between Lamport and vector clocks: a single Lamport number can never express "these two things simply have nothing to do with each other."

🏁 FINAL COMPARISON STUDENTS SHOULD KNOW

Lamport clocks vs. vector clocks

PropertyLamport ClockVector Clock
What it storesA single integerOne integer per process
Can detect A → B?Yes, if it truly happenedYes, and more precisely
Can detect concurrency (A || B)?No — cannot distinguish from A → BYes — dominance check reveals it
Does L(A) < L(B) imply causation?No — false positives possibleDominance is exact — no false positives
Memory costO(1) — one numberO(n) — one slot per process
Typical use caseSimple total ordering, logsConflict detection, replicated data, version tracking

Vector clocks cost more memory as the system grows, but they're the only tool here that can tell independence from causation — which is exactly why systems like distributed databases and version-control tools rely on vector-clock-style reasoning.

RECAP

Hour 12 — Key takeaways

🧭 One counter per process

A vector clock tracks every process's progress, not just its own — closing the gap Lamport clocks leave open.

⚖️ tick + max + increment

Local events bump your own slot; receiving takes the component-wise max, then bumps your own slot again.

➡️ Dominance = causation

A → B exactly when A is ≤ B everywhere and strictly less somewhere — no false positives.

|| = genuinely independent

When neither vector dominates, the events are concurrent — something Lamport clocks alone could never prove.
