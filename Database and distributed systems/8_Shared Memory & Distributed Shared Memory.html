8.1 SHARED MEMORY

Two threads, one memory

Thread A
↓
🧠 Shared Memory
↑
Thread B

In a normal computer, both threads access the exact same memory — the same variables, the same objects, in real time.

This is fast and convenient — no network, no serialization, just direct access. But it means both threads can read and write at the same instant, and that's where today's problem begins.

8.2 RACE CONDITION

Two threads, one counter, one surprise

RaceConditionDemo.java 
class Counter {

    int count = 0;

    void increment() {
        count++;
    }
}

public class RaceConditionDemo {

    public static void main(String[] args)
            throws InterruptedException {

        Counter counter = new Counter();

        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 100000; i++) {
                counter.increment();
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 100000; i++) {
                counter.increment();
            }
        });

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println(
                "Final count: " + counter.count);
    }
}
8.2 RACE CONDITION

Why the count comes up short

STUDENTS EXPECT
200000

100,000 increments from each thread, added together.

WHAT ACTUALLY HAPPENS
< 200000

A smaller, often inconsistent value.

count++ looks like one instruction, but it's actually three: read count, add 1, write it back. If both threads read the same value before either writes, one increment gets silently lost. This is a race condition.

8.3 FIX USING SYNCHRONIZATION

Protecting the critical section

Counter.java 
class Counter {

    private int count = 0;

    synchronized void increment() {
        count++;
    }

    int getCount() {
        return count;
    }
}

Adding synchronized means only one thread at a time can execute increment() on this object — the other thread has to wait its turn. Now the critical section is protected, and no update can be lost.

Hour 8 — Key takeaways

🧵 Shared memory is direct

Threads on the same machine read and write the exact same memory — fast, but dangerous without care.

🏁 count++ isn't atomic

It's read-add-write — three steps that can interleave between threads and silently lose updates.

🔒 synchronized protects the critical section

Only one thread executes the protected method at a time, eliminating the race.

🌐 Distributed shared memory is an illusion

Physically it's separate machines and separate memory, faked over a network — with consistency, sync, latency, and failure costs.
