3.4 JAVA TOKEN RING

Implementing the ring in Java

TokenRing.java 
class TokenRing {

    private final int numberOfProcesses;
    private int tokenHolder = 0;

    public TokenRing(int numberOfProcesses) {
        this.numberOfProcesses = numberOfProcesses;
    }

    public void passToken() {

        System.out.println(
                "P" + tokenHolder + " has the token.");

        System.out.println(
                "P" + tokenHolder + " enters critical section.");

        System.out.println(
                "P" + tokenHolder + " exits critical section.");

        tokenHolder = (tokenHolder + 1) % numberOfProcesses;
    }
}

public class TokenRingDemo {

    public static void main(String[] args) {

        TokenRing ring = new TokenRing(4);

        for (int i = 0; i < 8; i++) {
            ring.passToken();
        }
    }
}

3.5 SUZUKI–KASAMI ALGORITHM

Token-based, but no fixed ring

Suzuki–Kasami is a token-based distributed mutual exclusion algorithm for systems where processes communicate by broadcast — there's no neat circle to pass the token around.

P1 wants CS
↓
BROADCAST REQUEST
P2
P3
P4
...

The token itself contains information that helps determine which requests remain outstanding — so instead of a fixed hand-off order, the token is sent directly to whoever needs it next, decided dynamically.

3.5 SUZUKI–KASAMI ALGORITHM

Three pieces of information to introduce

RN

Request Number

Each process tracks the highest request sequence number it has seen from every other process — like a per-process logical clock for CS requests.

Q

Token Queue

The token itself carries a queue of processes still waiting for it — so the holder knows exactly who to pass it to next.

LN

Token Array

Records the request number last granted for each process, carried inside the token itself.

Students don't need to memorize the implementation immediately — focus first on the algorithm's intuition: a broadcast asks everyone "do you need this?", and the token, as it moves, carries the bookkeeping needed to answer that question correctly next time.

RECAP

Hour 15 — Key takeaways

🎫 One token, one permission

Only the current token holder may enter the critical section — no voting required.

⭕ Token Ring is the simplest form

A fixed circular hand-off order — (tokenHolder + 1) % n is the entire algorithm.

🎙️ The microphone analogy sticks

Only the holder speaks — everyone else simply waits their turn.

📡 Suzuki–Kasami scales beyond a ring

Broadcast requests plus a smart token (RN, Q, LN) let the token go directly to whoever needs it next.
