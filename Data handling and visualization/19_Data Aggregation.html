7.1

What is Aggregation?

Summarizing multiple records into a smaller set of meaningful values

📊 Many Rows In, Few Numbers Out

Aggregation means summarizing multiple records into a smaller set of meaningful values. A sales manager may need to know:

Manager's questionPandas functionExample
Total revenuesum()sales["revenue"].sum()
Average order valuemean()sales["revenue"].mean()
Highest-value transactionmax()sales["revenue"].max()
Number of orderscount()sales["order_id"].count()
Total quantity soldsum()sales["quantity"].sum()
Aggregation: from records to metrics
📝
The core idea: an aggregation takes a whole column (a Series) and returns one value. The row-by-row detail is deliberately thrown away to reveal the big picture.

Create a Sales Dataset

Six orders, and a calculated revenue column

🧪 Build the Data

import pandas as pd

sales = pd.DataFrame({
    "order_id": [1001, 1002, 1003, 1004, 1005, 1006],

sales["revenue"] = sales["quantity"] * sales["unit_price"]

Common Aggregation Functions

Six metrics from the same data, each with a different story

🧮 Calculate the Core Metrics

aggregation_functions.py
print("Total revenue:", sales["revenue"].sum())
print("Average revenue:", sales["revenue"].mean())
print("Highest revenue:", sales["revenue"].max())
print("Lowest revenue:", sales["revenue"].min())

⚙️ Implementation Steps
  1. Choose the column that answers the questionRevenue questions use revenue; unit questions use quantity.sales["revenue"]
  2. Call the aggregation method, with parenthesesThe method reads every value in the column and returns one number.sales["revenue"].sum()
  3. Print it with a clear labelA label tells the reader what the number means.print("Total revenue:", sales["revenue"].sum())
  4. Repeat for each metricSwap sum for mean, max, min, count.
  5. Sanity-check against the tableFor example, the largest value in the revenue column is 100,000, so max() must print that.

⚖️ Mean vs Median: why two "averages"?

The mean adds everything and divides by the count. The median sorts the values and takes the middle. With six values there is no single middle, so the median is the average of the middle two.

Revenue sorted from smallest to largest
1st2,500
2nd4,500
3rd · middle5,000
4th · middle24,000
5th50,000
6th100,000
median = (5,000 + 24,000) ÷ 2 = 14,500  ·  mean = 186,000 ÷ 6 = 31,000
💡
Which should you report? When a few very large values exist (like the two laptop orders), the mean is pulled upwards and overstates what a "typical" order looks like. The median is steadier. Good analysts look at both.

🔢 count() vs size: the missing-value trap

With complete data they give the same answer, so students often assume they are identical. They are not: count() skips missing values, while size counts every row.

row 0100,000
row 1500
row 2NaN
row 34,500
row 45,000
row 524,000
count() → 5 (non-missing)  ·  size → 6 (all rows)
count_vs_size.py
import numpy as np

orders = pd.Series([100000, 500, np.nan, 4500, 5000, 24000])

print("count:", orders.count())
print("size :", orders.size)
print("len  :", len(orders))
print("sum  :", orders.sum())
print("mean :", orders.mean())
Outputcount: 5 size : 6 len : 6 sum : 134000.0 mean : 26800.0
📝
Two things to notice: (1) sum() and mean() quietly skip the NaN. The mean is 134,000 ÷ 5 = 26,800, not ÷ 6. (2) On a Series, size is written without parentheses.

In a group, size counts the group's rows even when a column is missing. Preview of grouped aggregation, with Order 1003's revenue blanked out:

groupby_preview.py
demo = sales.copy()
demo.loc[2, "revenue"] = np.nan   # Order 1003 (a Laptop) loses its revenue

print(demo.groupby("product")["revenue"].count())
print(demo.groupby("product").size())
Outputproduct Keyboard 1 Laptop 1 Monitor 1 Mouse 2 Name: revenue, dtype: int64 product Keyboard 1 Laptop 2 Monitor 1 Mouse 2 dtype: int64

The Laptop group has 2 rows (size = 2) but only 1 revenue value (count() = 1).

7.4

Aggregate Multiple Columns

One agg() call, a dictionary of column → list of functions

🧾 Build a Summary Table with agg()

agg_summary.py
summary = sales.agg({
    "quantity": ["sum", "mean", "max"],
    "revenue": ["sum", "mean", "max"]
})

print(summary)
Output quantity revenue sum 23.000000 186000.0 mean 3.833333 31000.0 max 10.000000 100000.0
How the dictionary becomes the table
the dictionary
{
  "quantity": ["sum", "mean", "max"],
  "revenue":  ["sum", "mean", "max"]
}

Keys = columns to summarize.
Values = the list of functions for that column, written as strings.

quantityrevenue
sum23.000000186000.0
mean3.83333331000.0
max10.000000100000.0
💡
Reading the result: each column of the output is one of your keys and each row is one function. sum of quantity (23) matches the "Total units sold" from 7.3, and sum of revenue (186,000) matches "Total revenue". agg() is just those six separate calls done in one step.
📝
Why do the numbers show decimals? Because mean produces decimals, Pandas stores each result column as floating-point, so even the sum shows as 23.000000.
⚙️ Implementation Steps
  1. List the columns you want to summarizeHere: quantity and revenue.
  2. Choose functions for each columnUse a list of function names as strings, such as ["sum", "mean", "max"].
  3. Put them in a dictionaryColumn name as key, list of functions as value.
  4. Pass the dictionary to agg()Store the result in summary.summary = sales.agg({...})
  5. Print and cross-checkCompare against the single-metric results from 7.3.print(summary)
7.5

Calculate Percentage Contribution

How much of the total does each order account for?

🥧 Each Order's Share of Total Revenue

percentage_contribution.py
total_revenue = sales["revenue"].sum()

sales["revenue_percentage"] = (
    sales["revenue"] / total_revenue
) * 100

print(sales[["order_id", "revenue", "revenue_percentage"]])
Output order_id revenue revenue_percentage 0 1001 100000 53.763441 1 1002 2500 1.344086 2 1003 50000 26.881720 3 1004 4500 2.419355 4 1005 5000 2.688172 5 1006 24000 12.903226

Example: Order 1001 → 100,000 ÷ 186,000 × 100 = 53.76%. A whole column is divided by a single number, so Pandas applies it to every row at once.

Self-check: the percentages must add up to 100. Run sales["revenue_percentage"].sum() and you get 100.0. If not, something in the formula is wrong.
⚙️ Implementation Steps
  1. Calculate the total once and store itA single number, reused for every row.total_revenue = sales["revenue"].sum()
  2. Divide the revenue column by the totalGives each order's share as a fraction between 0 and 1.sales["revenue"] / total_revenue
  3. Multiply by 100 to convert to a percentageKeep the division in parentheses so the order is clear.(sales["revenue"] / total_revenue) * 100
  4. Store it in a new columnAssigning to a new name creates revenue_percentage.
  5. Select the columns to show and verifyUse the double-bracket selector from Part 1, then check the column sums to 100.print(sales[["order_id", "revenue", "revenue_percentage"]])

Common Mistakes

Errors students make most often in this topic

1️⃣
Aggregating the wrong column
sales["unit_price"].sum() gives 114,500, which means nothing. Calculate revenue first, then sum that.
2️⃣
Using count() to count rows
It skips missing values. To count all rows, use len(sales) or size.
3️⃣
Forgetting * 100
Without it you get fractions such as 0.5376 instead of 53.76.
4️⃣
Reading only the mean
Mean revenue is 31,000, but the median is 14,500. Large orders can make the mean misleading.
5️⃣
Missing parentheses
sales["revenue"].sum (no brackets) prints the method itself instead of the total.
6️⃣
size on a whole DataFrame
sales.size is rows × columns = 36 here, not the 6 rows. Use len(sales) for rows.
