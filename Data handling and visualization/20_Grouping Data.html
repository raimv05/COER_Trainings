8.1

What is Grouping?

Divide records into categories, then summarize each category

📘 Definition

Grouping means dividing records into categories and calculating a summary for each category. A business might compare sales by city or revenue by product.

Pandas does this with the split–apply–combine approach:

1 · Split

Delhi2 rows
Mumbai2 rows
Pune2 rows
→

2 · Apply

Delhisum(100000, 2500)
Mumbaisum(5000, 150000)
Punesum(50000, 4000)
→

3 · Combine

Delhi 102500
Mumbai 155000
Pune 54000

Split the rows by city → apply sum() inside each group → combine the answers into one result.

💡
Last hour vs this hour: sales["revenue"].sum() gives one number for the whole table. sales.groupby("city")["revenue"].sum() gives one number per city.

8.4

Group by Product

Several labeled statistics in one call

📦 Named aggregation

Pass name=("column", "function") pairs to agg(). The name becomes the output column heading.

group_by_product.py
product_summary = sales.groupby("product").agg(
    total_quantity=("quantity", "sum"),
    total_revenue=("revenue", "sum"),
    average_revenue=("revenue", "mean"),
    number_of_records=("revenue", "size")
)

print(product_summary)
Output total_quantity total_revenue average_revenue number_of_records product Laptop 6 300000 100000.000000 3 Mouse 23 11500 3833.333333 3

Anatomy of one pair
total_revenue=("revenue", "sum")
new column name → source column → function
Why size?
number_of_records=("revenue", "size") counts every row in the group, including missing values.
⭐
Professional pattern: use named aggregations to produce clearly labeled output columns. A reader sees total_revenue, not an ambiguous sum.
8.5

Group by Multiple Columns

One group per city–product combination

🧱 Passing a list of columns

group_by_multiple.py
city_product_summary = sales.groupby(
    ["city", "product"],
    as_index=False
).agg(
    total_quantity=("quantity", "sum"),
    total_revenue=("revenue", "sum")
)

print(city_product_summary)
Output city product total_quantity total_revenue 0 Delhi Laptop 2 100000 1 Delhi Mouse 5 2500 2 Mumbai Laptop 3 150000 3 Mumbai Mouse 10 5000 4 Pune Laptop 1 50000 5 Pune Mouse 8 4000

3 cities × 2 products = 6 groups, each with exactly one row in this small dataset.

💡
What does as_index=False do? Without it, city and product become the row index. With it, they stay as ordinary columns, so the result is a flat table that is easy to print, export or merge.
8.6

Calculate Group Percentages

Each order's share of its own city's revenue

📊 transform("sum")

group_percentages.py
sales["city_total_revenue"] = (
    sales.groupby("city")["revenue"].transform("sum")
)

sales["percentage_of_city_revenue"] = (
    sales["revenue"] / sales["city_total_revenue"] * 100
)

print(sales)

The teal columns are new. city_total_revenue repeats on every row of a city; the percentages within each city add up to 100.

transform vs. a plain groupby

groupby().sum()

Summarizes. 6 rows in → 3 rows out, one per city.

Delhi 102500
Mumbai 155000
Pune 54000

groupby().transform("sum")

Aligned with the original rows. 6 rows in → 6 values out, so it can be stored as a new column.

102500, 155000, 102500,
54000, 155000, 54000
Implementation steps
  1. Compute each city's total with groupby("city")["revenue"].transform("sum") and store it as city_total_revenue.
  2. Divide each row's revenue by its own city_total_revenue.
  3. Multiply by 100 to get a percentage.
  4. Check: percentages within each city should sum to 100 (e.g. Delhi 97.56 + 2.44).
🧠
Key idea to explain: transform("sum") returns a result aligned with the original rows, whereas groupby().sum() typically produces a summarized result.
