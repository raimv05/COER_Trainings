INDUSTRY MINI PROJECT · PROBLEM STATEMENT

E-Commerce Customer Data Cleaning

The capstone assignment for the Data Handling & Preprocessing course. No new theory — this hour is a practical assessment of everything covered across the previous eleven modules, applied to one realistic dataset.

OBJECTIVES

What this assessment measures

By the end of this project, a student should be able to take an unverified, messy dataset and turn it into something an analytics or ML team could use without hesitation.

1Profile a raw dataset systematically before making any changes to it.
2Detect and resolve duplicate records, inconsistent text, and missing values.
3Engineer a new business-relevant feature from existing columns.
4Normalize and standardize numeric features correctly, without data leakage.
5Justify every cleaning decision rather than applying fixes by default.
6Produce a reproducible script, not a one-off manual edit.
COURSE OUTCOMES MAPPED

Course outcomes

This project is the single assessment point that exercises every course outcome from the 12-hour series at once.

COOn completion, the student will be able to
CO1Distinguish structured, semi-structured and unstructured data, and identify common data sources and formats.
CO2Explore a dataset's shape, types and summary statistics to assess its quality before cleaning it.
CO3Apply cleaning operations — deduplication, text standardisation, type conversion — correctly and in the right order.
CO4Select and justify an appropriate missing-value strategy based on context, not habit.
CO5Engineer new features and encode categorical data for downstream analysis or modelling.
CO6Normalize and standardize numeric features while avoiding data leakage between train and test data.
SCENARIO

Brief

Your role: Junior Data Analyst

You work as a junior data analyst for an e-commerce company. The company has provided raw customer transaction data pulled directly from the production database.

Your job is to prepare this data for analytics — nobody downstream should have to second-guess whether a number in this dataset can be trusted.

Ten tasks, in the order a real cleaning pipeline actually runs — explore first, fix what's found, then transform and scale.

6Handle missing ageModule 07

# Assume average order value = ₹1,500

EMPHASIZE THROUGHOUT

Industry standards

These habits are what separate a student who can run pandas commands from one who can be trusted with production data.

1

Never modify the raw dataset directly

Keep raw inputs, processed outputs and source code in clearly separated folders.

project/
├── data/
│   ├── raw/
│   │   └── customers.csv
│   └── processed/
│      └── customers_clean.csv
├── src/
│   └── preprocessing.py
├── notebooks/
│   └── exploration.ipynb
└── README.md
2

Always inspect before cleaning

Bad approach
df.dropna()
Professional approach
df.info()df.isna().sum()df.describe()then decide what to do
3

Never assume missing values should become zero

For example, Salary = missing does not necessarily mean Salary = 0.

4

Keep data types correct

Age → numeric · Salary → numeric · Date → datetime · City → categorical/text

5

Validate after cleaning

validate.py
print(df.isna().sum())
print(df.duplicated().sum())
print(df.dtypes)

The goal isn't "I ran the cleaning code" — it's "I can demonstrate that the resulting data satisfies the expected quality rules."

6

Avoid data leakage

Especially important when preprocessing data for machine learning.

Correct
scaler.fit(X_train) X_train_scaled = scaler.transform(X_train) X_test_scaled = scaler.transform(X_test) shorthand: fit_transform(X_train), then transform(X_test)
Incorrect
X_train_scaled = scaler.fit_transform(X_train) X_test_scaled = scaler.fit_transform(X_test) lets test-set information leak into preprocessing
7

Reproducibility

A professional data-processing task should be rerunnable by anyone — not a one-time manual Excel edit.

Raw Data → Python Script → Clean Data

Recommended Python environment

WHAT TO SUBMIT

Deliverables

A single, runnable script or notebook — preprocessing.py or exploration.ipynb — that performs all 10 tasks in order.
The raw input file and the cleaned output file, kept in separate data/raw/ and data/processed/ folders.
Printed validation output (isna().sum(), duplicated().sum(), dtypes) proving the cleaned data actually meets quality rules.
A short README.md explaining each cleaning decision — especially the missing-value strategy — and why it was chosen.
