10.1

What is Merging?

Combining two datasets through matching columns called keys

📘 Definition

Merging combines information from two datasets using one or more matching columns, known as keys. Pandas supports SQL-style joins: inner, left, right and outer.

Imagine an e-commerce application that stores customers in one table and orders in another:

Customer table

Order table

To find out who placed each order, we link the tables through the shared customer_id column (amber/teal highlight).

customers (customer_id, name, city)
⇅ match on customer_id
orders (order_id, customer_id, amount)
↓ pd.merge()
order_id · customer_id · name · city · amount

The key column appears in both tables; the merge result carries columns from both sides.

10.3

Inner Merge

Only records with matching keys in both datasets

🤝 how="inner"

inner_merge.py
inner_result = pd.merge(
    customers,
    orders,
    on="customer_id",
    how="inner"
)

print(inner_result)

Use an inner merge when the output should include only matched records.

Left Merge

Keep every record from the left dataset

10.7

Validate Merge Relationships

Check that the join is shaped the way you expect

🛡️ validate="one_to_many"

A particularly important professional practice is checking whether the relationship between datasets is what you expect. If every customer ID should appear only once in the customer table, validate that assumption.

validate_merge.py
result = pd.merge(
    customers,
    orders,
    on="customer_id",
    how="left",
    validate="one_to_many"
)

print(result)
Output customer_id name city order_id amount 0 101 Rahul Delhi 5001.0 5000.0 1 101 Rahul Delhi 5003.0 2000.0 2 102 Priya Mumbai 5002.0 3000.0 3 103 Amit Pune NaN NaN 4 104 Sneha Delhi NaN NaN
Left table
Key must be unique — each customer appears once.
Right table
Key may repeat — a customer can place many orders.

The result is identical to the left merge in 10.4 — validation doesn't change the output; it stops the code if the assumption is false.

What a failed check looks like — added illustration
validate_fails.py
# Added illustration: claim the relationship is one_to_one
# (it is not: customer 101 has two orders)
pd.merge(
    orders, orders,
    on="customer_id",
    validate="one_to_one"
)
Raises an errorMergeError: Merge keys are not unique in either left or right dataset; not a one-to-one merge.
⚠️
This example is an added illustration. The error message names the problem (key not unique), so a bad assumption is caught immediately instead of silently producing wrong numbers.

🧠 Task 6 — why the wrong key breaks results

A merge only pairs rows whose key values are equal. If the key doesn't truly identify the same entity on both sides, the pairs are wrong — and Pandas will not warn you unless you use validate.

  • Wrong pairing: joining on a column that merely shares values (for example an order number against a customer number) matches unrelated records.
  • Duplicated rows: if the key is not unique on one side, every match is multiplied, inflating counts and totals.
  • Silent loss or NaN: keys that don't line up drop rows (inner) or fill NaN (left/right/outer) — and totals quietly become wrong.

Added illustration — customer 101 appears twice in a (messy) customer table, so each of his orders is matched twice:

dupc = pd.DataFrame({
    "customer_id": [101, 101, 102],
